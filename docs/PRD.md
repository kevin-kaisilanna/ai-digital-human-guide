# 景区导览 AI 数字人 — 产品需求文档 (PRD)

## 1. 产品定位

一款运行在手机或景区终端设备上的**智能导游应用**。游客打开应用即可看到一个会说话、有表情的虚拟数字人导游，随时随地获得景区讲解、路线推荐和问答服务。

---

## 2. 目标用户

| 用户类型 | 核心诉求 |
|---------|---------|
| 景区游客 | 走到哪问到哪；不想做攻略，想要一个靠谱的"私人导游"；不只是听解说，还能跟导游聊天互动 |
| 景区管理者 | 后台实时看到服务数据；能自己更新景区知识库，不用每次都找技术团队；了解游客在想什么、满意度如何 |

---

## 3. 要解决的痛点

1. **导游不够用** — 旺季人满为患，一个导游带几十人，跟不上的游客就听不到解说
2. **录音导览太死板** — "前方是XX景点，修建于XX年"，听完就忘，想问个问题也没地方问
3. **没有"人情味"** — 冰冷的电子设备，不会笑不会互动，和真人导游完全没法比
4. **管理者瞎了眼** — 不知道游客来了多少、问了什么、满不满意，服务改进全靠猜

---

## 4. 功能清单

### 4.1 游客端功能

#### 4.1.1 多模态交互 — 跟数字人聊天

**用户故事**：作为游客，我能用语音或打字的方式跟数字人导游说话，它会用声音、表情和口型动作回应我，就像面对一个真人导游。

**具体要求**：

- **输入方式**：支持语音输入（按住说话）和文字输入（打字发送），两种方式可随时切换
- **输出方式**：数字人用语音播报回答，同时嘴型同步（口型跟说的话对得上），脸上有对应的表情变化
- **唤醒方式**：点击主页面的数字人形象，或按下"说话"按钮开始交互
- **对话体验**：
  - 问问题后 5 秒内开始回答
  - 数字人说话时脸上有自然的表情（微笑、认真、好奇等），不是一张死板的静态图
  - 支持连续对话，上下文能接得上（比如先问"这个塔有多高"，再问"那是什么时候建的"，系统能明白"那"指的还是这个塔）

---

#### 4.1.2 智能问答

**用户故事**：作为游客，我能问任何跟景区相关的问题（历史背景、建筑特色、文化典故），数字人能给我准确、好懂的答案。

**具体要求**：

- 覆盖景区历史、文化、景点特色、设施位置（洗手间/餐厅/出入口）等常见问题
- 回答准确率 ≥ 90%（评审会用标准测试集验证）
- 回答风格口语化、有温度，像导游聊天一样，而不是念百科

**典型问题示例**：
- "这个亭子是谁建的？"
- "这里有关于李白的典故吗？"
- "前面那条路通向哪里？"
- "附近有卫生间吗？"
- "给我讲讲这座山的传说故事"

---

#### 4.1.3 个性化路线推荐

**用户故事**：作为游客，我想告诉数字人我的偏好（喜欢历史/喜欢自然风光/带小孩），它能给我推荐一条适合我的游览路线。

**具体要求**：

- 游客选择兴趣标签（如"历史人文""自然风光""亲子游""摄影打卡"），数字人据此推荐游览路线
- 推荐的路线包含：景点顺序、每站简要讲解要点、预计游览时长
- 每条路线在 3-5 个景点之间，不宜过多或过少
- （可选）如果能获取游客位置，还可以提示"你目前距离最近的推荐景点还有多远"

---

### 4.2 管理后台功能

#### 4.2.1 知识库管理

**用户故事**：作为景区管理员，我能自己上传景区的讲解资料和管理常见问答，不需要每次都找开发人员改代码。

**具体要求**：

- 支持上传文档（Word、TXT、PDF）作为数字人的知识来源
- 可以查看、编辑、删除已上传的知识条目
- 可以手动添加/编辑/删除常见问题及答案（FAQ）
- 知识更新后，数字人的回答能即时生效
- 显示每条知识的来源和更新时间

**页面布局**：
- 左侧：知识分类树（历史文化、景点介绍、设施信息、活动资讯等）
- 右侧：知识列表，每条显示标题、摘要、更新时间
- 顶部：搜索框 + 上传按钮 + 新建知识按钮

---

#### 4.2.2 数字人形象管理

**用户故事**：作为景区管理员，我能配置数字人导游长什么样、穿什么衣服、用什么声音，让它符合我们景区的文化调性。

**具体要求**：

- **外观配置**：选择数字人的性别、发型、脸型等基础外观
- **服装配置**：选择符合景区文化的服装风格（如汉服、民族服饰、现代职业装等）
- **声音配置**：选择语音风格（温柔女声、沉稳男声、活泼少女声等），可试听
- **背景图**：可上传景区实景图或品牌图作为数字人聊天背景

**页面布局**：
- 左侧：预览区，实时展示当前配置的数字人形象
- 右侧：配置面板，分"外观""服装""声音""背景"四个选项卡

---

#### 4.2.3 游客感受度报告

**用户故事**：作为景区管理员，我能看到游客问了什么、情绪怎么样，从而知道该优化哪些服务。

**具体要求**：

- **游客关注点分析**：统计游客最常问的问题类别，用饼图或柱状图展示
- **情感趋势报告**：分析游客对话中的情感倾向（满意/中性/不满），按时间统计趋势
- **热门问题排行榜**：列出被问最多的前 20 个问题
- **服务建议**：系统自动生成 3-5 条改进建议（如"最近10位游客询问该景点，但知识库中无此信息"）
- 支持导出 PDF 报告

---

#### 4.2.4 数据大屏概览

**用户故事**：作为景区管理者，我打开后台第一眼就能看到核心运营数据，不需要点来点去找。

**具体要求**：

大屏展示以下指标卡片（以当日和本周数据为主）：

- **今日服务人次** — 大数字展示，旁边标环比涨跌
- **本周服务人次** — 柱状趋势图
- **热门问答 Top 10** — 滚动列表
- **游客满意度趋势** — 折线图（满意/中性/不满三条线）
- **当前在线用户数** — 实时刷新
- **各景点关注热度** — 热力图或柱状图

**数据大屏作为后台首页**，登录后直接展示，一目了然。

## 5. 页面结构 (信息架构)

```
游客端 App
├── 首页（数字人交互界面）
│   ├── 数字人形象区（上半屏幕）
│   └── 聊天对话区（下半屏幕）
├── 侧边栏 / 底部导航
│   ├── 对话（当前页面）
│   ├── 路线推荐

管理后台 (Web)
├── 数据大屏（首页，登录后默认展示）
├── 知识库管理
├── 数字人形象管理
├── 游客报告
└── 系统设置
```

## 6. 页面设计说明

### 6.1 游客端 — 交互主页

这是游客打开 App 后最先看到的画面，也是最核心的页面。

**布局描述**：
- 上半区域（约占屏幕 60%）：数字人形象展示区。一个半身的虚拟人物居中显示，拥有自然的面部表情变化。背景可以用景区实景图或品牌图。当数字人讲话时，嘴型与语音同步，面部表情随内容变化（讲历史时庄重、讲传说时神秘、讲趣事时微笑）。
- 下半区域（约占屏幕 40%）：对话区，类似聊天软件界面。用户和数字人的对话以聊天气泡形式展示，往上滑动可查看历史记录。用户发语音时显示"语音 5''"的气泡，点击可回放。
- 底部：输入栏，包含语音按钮（按住说话）、文字输入框、发送按钮。语音按钮在左侧，输入框在中间，右侧是发送/切换图标。

**交互逻辑**：
- 首次进入，数字人主动打招呼并做自我介绍
- 点击数字人形象区可重新播放上一次的回答
- 对话气泡支持文本展示用户语音转写后的文字

### 6.2 游客端 — 路线推荐页

**布局描述**：
- 顶部：兴趣标签栏，横向滑动选择，如"历史人文""自然风光""亲子游""摄影打卡""全部"
- 中间：路线卡片列表。每张卡片展示：
  - 路线名称（如"一日看尽长安花 — 人文精华线"）
  - 路线预览图（手绘风格地图缩略图）
  - 经过的景点数量 + 预计用时
  - 推荐理由（一句话）
- 点击某条路线卡片进入详情：
  - 完整的景点顺序图（纵向时间轴样式）
  - 每个节点的讲解要点摘要
  - 可点击"开始导航"回到对话页，让数字人按此路线讲解

### 6.3 管理后台 — 数据大屏页

**布局描述**（宽屏 Web 页面）：

```
┌──────────────────────────────────────────────┐
│  顶部：Logo + 日期选择器 + 刷新按钮           │
├────────┬────────┬────────┬────────┬──────────┤
│ 今日服务│ 本周服务│ 当前在线│ 满意度 │ 知识库   │
│ 1,286  │ 趋势柱 │   32   │ 92.5% │ 156条   │
│ ↑12%   │ 状图   │ 人     │ ↑2.1% │         │
├────────┴────────┴────────┴────────┴──────────┤
│  左：热门问答 Top10（表格/列表）               │
│  中：满意度趋势（折线图，近7天）               │
│  右：各景点热度（柱状图）                      │
└──────────────────────────────────────────────┘
```

卡片用白色圆角卡片，配柔和阴影。数据通过彩色图标 + 大数字突出展示。趋势用绿色箭头（上升）和红色箭头（下降）标识。

### 6.4 管理后台 — 知识库管理页

**布局描述**：
- 左侧常驻导航栏（深色侧边栏）
- 右侧主内容区：
  - 顶部操作栏：搜索框、上传文档按钮、新建知识按钮
  - 左侧分类树：可展开/折叠的知识分类（历史文化、景点介绍、设施服务、活动资讯等）
  - 右侧表格：知识列表，每行显示标题、分类标签、更新时间、操作按钮（编辑/删除）
- 点击编辑：右侧展开抽屉或弹出对话框，显示知识详情编辑器（标题、分类、内容富文本编辑）

### 6.5 管理后台 — 数字人形象管理页

**布局描述**：
- 左侧（50% 宽度）：数字人实时预览，一个 3D 或高清 2D 数字人展示区
- 右侧（50% 宽度）：配置面板，分为四个标签页：
  - 外观：性别选择（男/女）、发型选择（多款缩略图）、脸型选择
  - 服装：风格列表（汉服、唐装、民族服饰、现代装等），点击即切换预览
  - 声音：声线列表，点击可试听 3 秒样本
  - 背景：可上传景区实景照片作为数字人背景

## 7. 非功能性要求

| 要求项 | 标准 |
|-------|------|
| 事实性问答准确率 | ≥ 90%（专家用标准测试集评测） |
| 语音问答响应延迟 | < 5 秒 |
| 系统稳定性 | 运行期间不崩溃、不长时间无响应 |
| 数字人表现力 | 口型同步、语音自然、表情适配 |
| 可用性 | 7×24 小时在线，游客随时可用 |

---

## 8. 可选的进阶方向（加分项）

1. 结合 GPS 定位，在游客靠近景点时自动触发讲解（"走到哪讲到哪"）
2. 支持景区内没有 GPS 信号时的替代定位方案
3. 多语言支持（面向入境游客）
4. 离线模式（下载离线包后无网络也能使用基础问答）

---

## 9. 术语约定

| 术语 | 含义 |
|-----|------|
| 数字人 | 屏幕上显示的虚拟人物形象，能说话、有表情、嘴型跟语音同步 |
| 多模态 | 同时支持多种交互方式：语音输入、文字输入、语音输出、表情输出、口型输出 |
| 知识库 | 存储景区讲解词、历史资料、常见问答等知识的数据库，是数字人回答问题的知识来源 |
| 游客感受度 | 通过分析游客对话内容和情感倾向得出的满意度评估 |
